## 3. 前置依赖

- 若依基础结构已导入（`sql/ry_20260320.sql`）。
- A2 迁移已应用：种子假定 `sys_user` 账号域已归一为 `00/01/02/03`。
- **必须早于 `A4_20260922_002__a4_permissions.sql`**：A4 前置检查要求顶级
  `path='user'` 目录唯一，而该目录由本种子 `menu_id=5142`（用户与创作者管理）提供。
- 若目标库此前已执行过 A4 权限迁移，则 `user/UserManage` 组件已被 `3001/3008` 占用，
  种子会按「组件唯一性」守卫跳过 `5142`。该场景由
  `sql/migrations/pc/PC_20260923_001__sidebar_ia.sql` 第 0 步按最终形态补写，
  请按 `sql/migrations/README.md` 的顺序执行，不要手工补菜单。

## 4. 种子写入范围

| menu_id 段 | 内容 | 数量 |
| --- | --- | --- |
| 5000–5006 | 产品一级分组目录（工作台/内容与作品/数据统计/版权审核管理/交易商务管理/平台运维管理/AI创作与福利） | 7 |
| 5100–5152 | 产品叶子菜单（含组件与权限标识） | 25 |
| — | `sys_role` 新建受限运营角色 `a1_operator` + 4 条菜单授权 | 1+4 |

守卫规则（决定了空库与已有库的差异）：

- `system` / `monitor` 顶级根已存在时不再新建占位根，禁止出现平行根目录。
- 叶子菜单按 `component` 去重：标准库已有的 `system/user/index` 等 8 个组件不会重复建菜单。
- 角色只新建、不改写既有 `sys_role.remark`；授权只覆盖 `remark LIKE 'A1SEED%'` 的菜单，
  且仅限工作台、数据统计、数据总览、运营数据总览 4 项。

**有意保留的重复 `component`**：`common/ModuleScaffold` ×9、`copyright/ReviewWorkbench` ×2。
单条 `INSERT .. SELECT` 内 `NOT EXISTS` 按语句开始前的表状态求值，因此同批同 `component`
的行会全部插入；前端按 `perms` 分卡片渲染，这是设计如此。数据不受影响，请勿"修正"。

## 5. 校验说明

`A1_20260921_001__p5_menu_verify.sql` 分两段：

1. **证据输出**：与原 shared 区 v5 校验脚本一致（`ROOTS` / `A1SEED_COUNT` / `P0_LEAVES` /
   `ROLE` / `ROLE_GRANTS` / `G1_STD` / `DUP_COMPONENT`），供人工核对与留档。
2. **判定项**：15 项写入临时表，末尾输出 `SUMMARY`。`result` 必须为 `PASS` 且
   `fail_cnt=0`。覆盖根目录唯一性、7 个分组、25 个叶子、关键路径、权限标识完整性、
  父子引用完整、角色与授权边界、若依原生体系未被改写。

**阶段限制**：判定项断言的是 A1 阶段形态（`5100.path='dashboard'`、
`5142/5143/5150/5151/5152` 挂在根下）。PC 迁移会按原型重挂层级并改成绝对路径，
之后本校验会报 `FAIL`，属于预期行为——PC 之后请用
`pc/PC_20260923_001__sidebar_ia_verify.sql`。

## 7. 回滚

`U20260921_001__p5_menu_rollback.sql` 只按 `remark` 前缀删除自身写入的菜单与授权，
并只删除 `remark='A1SEED-CREATED'` 的新建角色。若已执行 PC 迁移，先回滚 PC，
否则会连带删除已被 PC 改写的产品菜单。详见 `sql/migrations/README.md` 第 6 节。
