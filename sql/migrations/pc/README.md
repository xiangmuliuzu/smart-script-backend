## 4. 做了什么

| 步骤 | 内容 |
| ---: | --- |
| 0 | **补齐 `5142`**：A1 种子的「组件唯一性」守卫生效时（`user/UserManage` 已被 A4 的 `3001/3008` 占用）会跳过该菜单，这里按最终形态（`parent_id=5005`、`path='/user'`）补写，仅当 `menu_id=5142` 不存在时插入 |
| 1 | 顶级分组顺序：工作台 → 内容与作品 → 版权审核管理 → 交易商务管理 → 平台运维管理 → AI 创作与福利 → 数据统计 → 系统管理 → 用户中心 |
| 2 | 产品叶子回到原型层级，并改写为绝对路径：`5100→/dashboard`（挂 5000）、`5142→/user`、`5143→/risk`（挂 5005）、`5150→/ai/operations`、`5151→/support/welfare`、`5152→/support/messages`（挂 5006） |
| 3 | 名称对齐：`5123`→版权资产库管理、`5006`→AI 创作与福利、`5150`→AI 创作与次数 |
| 4 | 去 `A4` 前缀：`3000`→用户中心、`3001`→App用户与创作者、`3005`→实名审核、`3008`→作者能力、`3010`→用户消息、`3013`→用户反馈（`F` 类型按钮名不变） |

绝对路径是有意为之：`Dashboard.vue` 的快捷入口硬编码引用
`/copyright/ai-review`、`/trade/orders`、`/user`、`/risk`，改成相对路径会破坏这些跳转。

该脚本不改 `menu_type` / `perms` / `visible` / `status` / 组件，因此不改变任何权限判定，
`sys_menu` 之外的表一行都不动（不涉及 `sys_role` / `sys_role_menu` / 业务表）。

## 5. 最终校验

`PC_20260923_001__sidebar_ia_verify.sql` 共 17 项判定，末尾 `SUMMARY` 的 `result`
必须为 `PASS` 且 `fail_cnt=0`，覆盖：

- 原根级散叶子清零；25 个 A1 产品叶子不再挂在根上
- `5100` 挂 `5000` 且路径为 `/dashboard`；`5142/5143` 挂 `5005`；
  `5150/5151/5152` 挂 `5006` 且为绝对路径
- 顶级目录顺序 9 项、名称对齐 9 项、`A4%` 命名清零
- A4 菜单体系完整（`3000-3015` 共 16 个 = 1 目录 + 5 页面 + 10 按钮，用户中心下 5 个页面）
- `5142` 已按最终形态存在（第 0 步补齐生效）
- `a1_operator` 授权仍为 4 条（本次迁移不得改变授权）
- 无孤儿父子引用、同级路由路径唯一、`route_name` 唯一、若依原生 `menu_id=100` 未被改写

同时输出侧边栏树、用户中心子菜单与全局计数（表/用户/角色/菜单/角色菜单）作为证据。
