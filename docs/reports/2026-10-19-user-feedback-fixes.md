# 用户中心测试反馈修复记录

范围：修复以下 8 项。按用户补充要求，RISK_003 不处理。

| 用例 | 根因及修复 |
| --- | --- |
| RNAUDIT_001 | 请求层已解包响应，原查看函数仍读取 `res.data.accessUrl`，导致无法获取访问链接。新增共用材料预览组件，使用解包后的链接请求文件，PNG/JPEG/GIF/WebP 按文件签名确认后在页面预览；其他类型下载，不内联执行 HTML/SVG。消费一次性令牌后自动刷新详情引用，支持重复查看。反馈附件复用同一实现。 |
| FEEDBACK_001 | 管理端仅识别 BUG/SUGGESTION/OTHER，与 App 实际提交的 FEATURE/EXPERIENCE/BUG/COMPLAINT/OTHER 不一致。显示和筛选统一为 App 当前枚举；兼容旧 SUGGESTION 显示，未知分类显示“其他”，不直接展示异常原始值。 |
| CREATOR_001 | 作者能力开关未检查最近申请的驳回状态。列表增加 `creatorApplicationStatus`，驳回且未开通时按钮置灰并显示原因；后端共享能力变更服务拒绝直接开通，即使绕过页面调用接口也不能成功。重新提交后按最近申请状态判定。 |
| APP_CREATOR_001 | 创作页面和创作接口仅校验登录。页面未开通能力时不查询作品、不显示新建，提示先申请并提供入口；创作子页面深链重定向到申请页。后端创建、上传、章节编辑、提交审核等接口统一校验当前能力，关闭后旧令牌也不能继续创作，失败返回 HTTP 403 及 App 响应信封。 |
| APP_CREATOR_002 | App 使用账号类型隐藏申请入口，且后端将历史 APPROVED 永久视为不可再次提交。申请入口和创作入口改按当前能力判断；历史已通过且能力被显式关闭时，对 App 恢复为可申请状态。重新申请新增 PENDING 记录，保留历史审核记录；仍阻止审核中的重复申请及已开通能力用户再次申请。不改写账号类型。 |
| FLT_001 | 用户管理新增独立“昵称（精确匹配）”筛选；去除首尾空格，重置页码，后端用参数绑定的 `u.nick_name = #{nickname}` 查询。保留已有综合关键字查询。 |
| FLT_002 | 创作者审核新增相同精确昵称筛选，在数据库分页前筛选，翻页保留条件，重置清除条件。 |
| FLT_003 | 用户反馈新增相同精确昵称筛选，支持以 `14786152186` 等完整昵称匹配，不与反馈内容、账号等综合关键字条件混用。 |
