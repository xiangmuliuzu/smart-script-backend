# 创作者作品删除（App 与共用后端）

## 用户流程

App「创作 → 我的作品 → 作品工作台 → 设置」底部提供红色「删除作品」。
网页创作者端在作品详情顶部提供「删除作品」，复用同一后端及验证规则。
确认弹窗展示作品名称及删除影响，用户主动获取绑定手机号的短信验证码，输入后确认删除。
成功后关闭工作台、刷新我的作品；失败保留弹窗并显示原因。用户可取消，提交期间禁止重复操作。

## 接口

- `POST /api/v1/content/works/{workId}/delete-code`：需要 App 登录及创作者能力；服务端确认本人未删除作品且无交易关联后，向账号绑定手机号发码。成功返回 `{sent: true, phoneMasked, cooldownSeconds}`。不接受客户端指定手机号。
- `DELETE /api/v1/content/works/{workId}`：JSON body `{code: "短信验证码"}`，code 必填。旧版无验证码的请求不再允许删除。
- 沿用 App 信封 `{code, message, data}`；不存在、已删除或非本人统一返回 404；关联订单、线下合作或付费解锁返回 409，提示下架；验证码沿用认证模块错误码、有效期、失败上限和频控。

## 后端边界

验证码使用独立 `DELETE_WORK` 场景，与登录、换绑等场景隔离；每次删除消费一次验证码。
内容模块通过公共验证接口调用认证模块，不直接读取认证表或依赖用户模块。
服务端每次发码、删除均检查归属和交易关联。订单包含其关联的合同，保留所有历史交易。
删除沿用 `sys_work.is_deleted`，同时下架并关闭交易；不物理删除章节、文件或历史记录。
验证码消费与逻辑删除在同一事务内，删除失败回滚；短信错误计数沿用独立事务。

## 验证与部署

测试覆盖 App 的确认/取消、发码失败、验证码错误、成功返回列表；后端覆盖无验证码、越权、交易拦截和一次性场景验证。
短信仍通过现有 `SmsProvider`，本仓库当前只有本地/测试 mock 实现；生产真实短信接入不在本次改动范围，不能声称已验证真实短信送达。
